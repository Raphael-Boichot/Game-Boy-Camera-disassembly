# Game Boy Camera (USA, Europe) (SGB Enhanced)

MD5 `42d2f65e2549be9d1d126a6828b5d1c1`. The international ROM: the same modes and states as the Japanese one in a different build (44.5 % of the bytes differ, mostly blocks moved by a fixed offset); the behavioural comparison with the Japanese ROM is in [`docs/16_menus_international_rom_bgb.md`](../../docs/16_menus_international_rom_bgb.md).

![What each byte of the international ROM is](us_rom_layout_map.png)

The symbol file is **ported from the Japanese tables** (method, counts and levels: [docs §1.5](../../docs/01_toolchain_and_status.md#15-the-international-rom-symbol-file-ported-from-the-japanese-one)):

| File | What it is |
|---|---|
| `gbcam_us.sym` | the mgbdis symbol file (generated by `tools/sym_build.py`; mgbdis reads it beside `gbcam_us.gb`) |
| `disasm/sym_names_us.csv`, `disasm/sym_types_us.csv` | **the names and type rows of this ROM** (C 5,281 / I 130): the merge of the layers below, written by `tools/merge_name_layers.py --tag us`; never edit them |
| `disasm/sym_unconclusive_us.csv` | the names left at I, with their readers here and in the Japanese ROM (`tools/port_check_names4.py`) |
| `disasm/layers/sym_{names,types}_us_port.csv` | layer 1: names and type rows carried from the Japanese tables (`tools/port_syms.py`: rerunning the port overwrites them) |
| `disasm/layers/sym_{names,types}_us_loaders.csv` | layer 2: blocks loaded by this build's own copy calls where no carried name sits (`tools/port_assets.py`) |
| `disasm/layers/sym_{names,types}_us_reads.csv`, `sym_names_us_checked.csv` | layers 3-4: blocks placed by their readers (`tools/port_reads.py`), carried names confirmed from this build's evidence (`tools/port_check_names*.py`) |
| `disasm/layers/sym_{names,types}_us_hand.csv` | layer 5: hand corrections and new names of this build, applied last (kept across re-ports): edit this one, then rerun `tools/merge_name_layers.py --tag us` |
| `intake/` | L0: the header, the per-bank comparison with the other ROMs and the no-symbol round trip (`tools/rom_intake.py`) |
| `disasm/ram_names_us.csv`, `ram_exclude_us.csv`, `ram_highbyte_us.csv`, `const_*_us.csv`, `sound_names_us.csv`, `state_names_us.csv`, `state_helpers_us.csv` (+ `_hand`), `state_shared_us.csv`, `wram/wram_access_us.csv` | the L4 tables of this build (`tools/port_l4.py`, `tools/state_names.py`) |
| `src/` | the editable source tree (L5), generated by `tools/make_source.py --tree us_eu`; `make TREE=us_eu check` at the top of the repository builds it |
| `disasm/rom_operands_us.csv`, `disasm/rom_operands_manual_us.csv`, `port/cov_jp_in_us.npz` | the ROM-address decisions of the tree, the hand ones, and the Japanese coverage carried through the maps that they use |
| `trace/trace_us.json` | static trace of this ROM (`tools/rom_trace.py --config trace/trace_config_us.json`), 0 unresolved |
| `trace/cov_us_runs.npz`, `trace/cov_us_witness.npz`, `trace/rom_map_us.csv` | the runs of this ROM in the core (organic, witness) and the byte map of the trace |
| `port/code_map_us.csv` | Japanese instruction -> international instruction (same / operand / imm) |
| `port/map_segments_us.csv`, `port/map_inserted_us.csv` | the byte map as segments of constant shift, and the international bytes no Japanese byte maps to |
| `port/port_report_us.csv` | every Japanese name and where it went (or why not) |
| `port/hand_queue_us.csv` | what is left to do by hand: new code, lost names, names to check, untyped data |
| `trace/trace_config_us.json`, `trace/extra_roots_us.json` (+ `extra_roots_us_hand.json`), `trace/rom_trace_labels_us.sym` | the tracer inputs carried through the map |

Build the ROM from the tree: `make TREE=us_eu check` (rgbds 1.0.4 in `PATH` or `RGBDS=`). Regenerate the tree after a table change: `make source TREE=us_eu ROM=gbcam_us.gb`.

Rebuild everything (the ROM is not in the repository: supplied by the owner outside it, md5 `42d2f65e2549be9d1d126a6828b5d1c1`; rgbds 1.0.4 via `RGBDS=`):

```bash
python3 tools/port_build.py pocketcamera_jp.gb gbcam_us.gb --mgbdis /path/to/mgbdis.py     # md5 42d2f65e2549be9d1d126a6828b5d1c1 three times (plain, --tables, --const)
```

By hand, the listing:

```bash
cp gbcam_us.gb roms/us_eu/gbcam_us.sym build/
python3 mgbdis.py build/gbcam_us.gb --output-dir build/us --print-hex
D=roms/us_eu/disasm
python3 tools/sym_fix.py build/us --rom build/gbcam_us.gb --trace roms/us_eu/trace/trace_us.json --tables --far-helpers 0473,049C,061B,068D,0734,0950,0956 \
  --const --ram-names $D/ram_names_us.csv --ram-access roms/us_eu/wram/wram_access_us.csv --ram-exclude $D/ram_exclude_us.csv --ram-highbyte $D/ram_highbyte_us.csv \
  --const-names $D/const_names_us.csv --const-types $D/const_types_us.csv --const-tables $D/const_tables_us.csv --const-sounds $D/sound_names_us.csv \
  --state-names $D/state_names_us.csv --state-helpers $D/state_helpers_us.csv --text-tables $D/text_tables_us.csv --charmap $D/charmap_us.inc,roms/jp_rev_a/disasm/charmap_jp.inc
cd build/us && make && md5sum game.gb
```

The text tables of this build (`disasm/text_tables_us.csv`: the keyboard lists A and B, and the Japanese leftovers) are written with its own character map `intl` (`disasm/charmap_us.inc`, from `disasm/charset_us.csv`, `tools/charset_us.py`) and the Japanese map `kana` for the leftovers (docs §1.2 item 5, L6, 2026-11-02).
