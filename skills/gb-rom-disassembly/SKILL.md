# Disassembling a Game Boy ROM (playbook from the Pocket Camera (Japan) Rev A project)

Full version: `HOWTO_NEW_ROM.md` in the Game-Boy-Camera-disassembly repository (README section 1.3 has the measured status of that ROM). Read the repo's `CLAUDE.md` first when working in it. The ROM is never in the repository: ask for it and for every sibling ROM (region, revision, edition).

## Say which level a claim is about

| Level | Meaning | Test |
|---|---|---|
| L0 | listing reassembles to the same md5 | `make` prints the md5 |
| L1 | every byte typed (code, data with row width, text, padding) | the `.sym` has no hole |
| L2 | code proven by a recursive-descent trace (0 unresolved indirect jumps) and observed in an emulator | trace + coverage report |
| L3 | every routine and asset named, tagged C / I / ?, doubts listed | names CSV + doubts CSV |
| L4 | RAM variables and constants applied in the source (no raw `[$D5CE]`) | grep for raw RAM operands |
| L5 | committed, buildable, editable tree: split files, assets as INCBIN, md5 check in `make` | tree in git |
| L6 | understanding: charset table, sibling ROMs, owner-validated names | owner answers file |

Pocket Camera JP (measured 2026-10-14, README §1.3): L0-L2 done, L3 mostly (5,347 names: C 4,011 / I 1,336 / ? 0, 111 doubtful rows on 10,445 distinct bytes), L4 done (789 RAM names applied to 10,239 instructions; 1,066 operands, 62 mode-table bytes and 230 sound-list bytes read as `MODE_*`, key-mask, hardware-flag and `MUSIC_*` / `SFX*_*` sound-id constants; 371 `STATE_*` constants of 34 modes at 383 state stores and 39 table bytes), L5 not done, L6 partial. Do L0-L2 first, but start L4 and L5 as soon as L2 exists: they were left to the end.

## Stages, in order

1. **Intake.** md5, header `$0100-$014F` (MBC type, sizes, flags), diff siblings per bank (the two Pocket Camera ROMs differ in 44 % of their bytes: traces do not transfer). Pin `rgbds` (1.0.4 wants `ldh a, [$FFxx]`) and `mgbdis` master after the v3.0 tag (v3.0 ignores the `.data` row width and `.padding`, silently). Round trip with NO symbols first: `python3 mgbdis.py --output-dir out rom.gb && cd out && make`; fix any md5 difference before anything else.
2. **Symbol file = single source of truth.** mgbdis v3.0 has no `--sym` option: it reads `<rom basename>.sym` beside the ROM (`BB:AAAA Name`, block lines `.code:LEN`, `.data:LEN[:WIDTH]`, `.text:LEN`, `.padding:LEN`, LEN in hex). Never edit the `.sym` by hand: keep `sym_names_*.csv` (`bank,addr,name,conf,note,source`, layers assets < auto < hand < fixes, name `-` deletes) and `sym_types_*.csv` (`bank,start,end,type,width,note`), plus the trace, and a builder that aborts on duplicate names, labels inside instructions, holes, overlaps and non-uniform padding. Naming: `Module_Verb` PascalCase; assets `Gfx_BB_AAAA_...`, `Map_...`, `Src_BB_AAAA_...`. Tag every name C (code read / emulator / BGB) / I (inferred) / ? (doubt) and regenerate the doubts list after every rename.
3. **mgbdis artefact.** It prints a label for any operand equal to a label's address (`ld bc, Label` as a byte count, `ld [Label], a` as an MBC write, far pointers in the wrong bank, word tables as `db`). A post-pass (`sym_fix.py --tables`) rewrites what the instruction bytes decide; bytes and md5 do not change. Extend its rules for each ROM.
4. **Static tracer.** Recursive descent from the vectors, entry point, labels, mode/state tables, then hand roots with a reason each. Teach it the engine helpers first (banked call, one-way far jump, banked copy, `rst` jump tables with inline words, wait loops). List unresolved indirect jumps (`jp hl`, computed calls), resolve each by hand (table idiom, split immediates, cooperative task entries, RAM callbacks), repeat until 0. Cap an inline `rst` table at the lowest target seen (one table was read a word too long and swallowed a handler's first instruction). Reachable is not live: keep unreferenced roots as dead roots. Feed the tracer only the first-pass labels (`tools/rom_trace_labels.sym`), never the finished symbol file: it takes every non-`.data` name as a code root.
5. **Assets.** Catalogue every banked copy call with constant bank/source/destination/length. A far pointer counts only if the immediate reaches the helper unchanged (`ld hl,TABLE; add hl,bc; ld a,[hl+]` is a local table). Render 2bpp sheets 16 tiles wide and maps 32 wide; typing by picture is allowed but tagged. Outside pictures (TCRF, Spriters Resource) may be 2x enlargements; a 1-2 tile exact match is weak. Banks with no static reference are found with an emulator ROM-read log.
6. **RAM map, then wire it in.** Build the access database (every instruction touching `$C000-$DFFF`, `$FF80-$FFFE`, I/O; R / W / pointer-load kinds; read-modify-write through HL is invisible). One CSV per region with name, type, writers, readers, evidence tag. Use real cartridge saves for the SRAM layout (checksums, mirrors, magic). Then apply the names with a per-site pass, not through the `.sym`: mgbdis would substitute by address equality (no bank scope, no `name + offset`, it names lengths and masks that equal an address, and an overlay area `$C000-$D4FF` has several buffers per address). Keep a names table with a scope per row (`*`, bank, routine, instruction), an exclusion list, and rewrite each operand from the instruction bytes and the access database (R / W operands are addresses; a 16-bit immediate only where a pointer load is recorded). Generate the include (`DEF wMode EQU $D5CE`) and a separate `.sym` for the debugger. Constants the same way: name the modes after their entry labels, type the operands that hold them (`wMode`, key bytes, LCDC shadow), rewrite `ld a, imm` before a store and `cp` / `bit` / `and` right after a load only on a straight line (no label, A untouched), list the mode byte tables by hand, reuse the `hardware.inc` flag names; name the sound ids from the routines that request them; name states per mode from the state tables and the handler labels (a store takes the mode set just before it, else the mode of its `ModeNN_` routine; a {mode, state} table byte takes the mode before it).
7. **Dynamic evidence.** Own SM83 core with coverage (fast, fuzzed joypad taps, single keys and 34 chords, seeded with real saves, replayable corpus) then BGB (the judge). What remains is gated by data, not keys: direction pressed while A is held, counter wraps, filled tables, out-of-range cursors, save contents. Poke WRAM/SRAM between frames (a variable recomputed every frame cannot be forced; a value known only inside a frame needs a two-pass snapshot/restore). Table overruns run garbage: count them separately, never as designed paths. Forcing: jump to an unreferenced function at a safe idle point (the main thread's halt/wait), flip a gating branch, replay in BGB through a hook in free bank-0 bytes called from the main loop. Forced dead code stays evidence I.
8. **BGB harness.** Demo file = one joypad byte per frame (A=1 B=2 Select=4 Start=8 Right=$10 Left=$20 Up=$40 Down=$80), 250-frame boot hold, `xvfb-run wine bgb.exe -hf` (`-headless` if linked runs stall), `-stateonexit` for RAM/VRAM/OAM, `-screenonexit` (160x144 only), `-br` breakpoints, 2 workers (about 250 runs in 4 minutes), long jobs with `setsid nohup`. **Ask BGB with logging watchpoints, not with state dumps:** `-wp ADDR[-ADDR]/VALUE/FLAGS/MESSAGE` (flags `drwxj`, banked ROM address `BB:AAAA`, WRAM and HRAM work the same) logs the message to `debugmsg.txt` at every hit and keeps running, so one replay answers who reads, writes or executes a whole list. The message may hold expressions between `%`: `%pc%` (the accessing instruction; BGB stops before it runs), `%rombank%`, `%a%`, `%(d5ce)%` and `%(d5cf)%` (mode and state), `%(ADDR)%` (the value read, or the value before a write); the count of equal lines is a table of site x screen x value. Add a control watchpoint on a byte the replay certainly touches (0 must mean "not accessed"), test a new command line on one run, batch up to about 120 watchpoints per command line, replay the cheapest corpus entry of each mode / state signature on 2 workers with one BGB folder each (`BGB_DIR`: the ini and `debugmsg.txt` are per folder), and classify every hit against the access table (cold-boot clear = baseline; a site the table lacks is a pointer access or a finding; a static site that never fires is "not reached in these replays", not dead). Tools: `tcrf_check/tools/bgb_wp_probe.py`, `wram_probe.py`, `wram_probe_scen.py`, `wram_probe_report.py`. Screens that a corpus replay cannot reach (the link exchange between two BGB instances, the printer, the D.J. editor, menus the organic corpus skips) need a driver: `tcrf_check/tools/wram_probe_scen.py` runs the same list through `bgb_link_wp.py`, `bgb_print_run.py`, `bgb_print_wild.py`, `bgb_dj_print.py` and `bgb_run_race.py` (the environment variable `BGB_WP` hands the list to every BGB script; `PRN_ERR=` makes the printer answer an error status); a corpus root `_zero` / `_ff` needs a pseudo-save of 128 KB `$00` / `$FF` in `saves_pseudo/`; a long path recorded in the core can end on another screen in BGB (timing), so read the `end` line before a verdict. A frame-by-frame capture is one short run per frame (1-2 s each, 5-10 minutes for 300 on two workers): the picture is the displayed frame, the state can be a fraction of a frame ahead, so trust the picture for what is on screen and sample every 2-4 frames when 1-frame resolution is not needed (`tcrf_check/tools/menu_screen_gif.py capture`).
9. **Text, split tree, sibling ROM.** Find the font bank early and build the charmap from the glyph sheets: the glyph of a code is a tile pair at a fixed bank offset, the reading of each glyph is by eye (tag I), and a code is C only where an emulator screenshot matches the glyph pixel for pixel and the sentence reads (Pocket Camera: done for the name and comment fields, not for the other texts). Commit the generated listing or per-bank sources with assets as INCBIN and a `make check` that compares the md5 (not done). For a second region, trace it separately: the pair differed in 44 % of its bytes, so names do not port automatically.

## Pitfalls (all hit once)

- BGB refuses VRAM writes in PPU mode 3 (161 of 256 bytes landed); its logs are hex; its WAV time is not a constant offset (find a sound by content); it needs 3 more boot frames than the project's own core. Read register writes at the right pc, not the last write.
- A write watchpoint stops BEFORE the instruction: `%(ADDR)%` is then the old value and the new one is in `%a%` (for `ld [nn],a`). A watchpoint count of 0 without a control watchpoint proves nothing.
- Screenshots and asset comparisons come from BGB, never from the project's own core (it draws some screens wrongly).
- A hex parser that expected upper case found nothing in the lower-case `.sym` and produced a false "nothing is displayed" claim: test a parser on a known label.
- Never `pkill -f PATTERN` when PATTERN is in your own command line: kill by PID. Foreground calls over 120 s are killed.
- L3 lessons (2026-10-14): asset names that embed a caller go stale when function labels are refined (115 of 5,334 did): rename them in a batch with a log; a run of 16+ equal bytes becomes `.padding` and hides the extent of the table or map around it; before calling a block unreferenced check the copy-site ranges AND the custom loaders (lists of `{src,bank,dst,len}` records, tables indexed by a value x16 / x32, glyph fonts indexed by char code); a far pointer whose bank sits in `C` (not `A`) or in a record is invisible to a scan for `ld a,BANK`; an auto label made by `ld hl,imm` with a far bank can split a real table (found once, `09:6000`); a 3-byte table is a far-pointer table only if its reader hands the three bytes to a banked copy (record tables such as `{x; y; entry}` read as `{lo,hi,bank}` and cut real blocks), so compare each target with the copy length of the block it falls into; a hex comparison in awk reads `6E80` as a number (use Python); a "really unused" verdict can fall when a numeral or glyph table is found (one did); an auto-named table carries the kind the labeller guessed (`_Gfx`, `_Map`): 30 such tables here were positions, targets, cursor graphs, animations and pointer tables, so name each from its reader; type width 2 = word table and 3 = `{lo,hi,bank}` table for the listing post-pass, so leave byte pairs at another width.
- Audit lessons (2026-10-18, none is a count): (1) a number quoted in 5-8 places (README, CLAUDE.md, this file, HOWTO) drifts: write a consistency checker as soon as a second copy exists (`tools/check_repo_consistency.py` in the repository): one regex per quoted figure compared with the file it comes from, `need=` so that a reworded sentence fails instead of passing silently, a diff of every generated file against a fresh run, the md5 round trip; test each new pattern on the OLD file and sentence before trusting it; (2) a `?` / `_Aux` / by-eye label is a hypothesis: 3 of 8 changed when re-derived by exact tile matching over the whole ROM and the sibling ROM, a loader scan (immediates with the bank, pointer tables, the copy-site list) and the display tracker (value-matched: look for duplicates of the tiles); (3) a tile map is a block of fixed-width rows (18 x 32 here, 12 hidden columns) in chains: check the neighbours before fixing a start, type it as a map, and remember that in the type CSV the last row wins; (4) a name that carries an address carries its own, a continuation is `_Part<addr>`; (5) a generator that overwrites a hand-kept paragraph, or an input list that is a frozen snapshot, needs that said in its docstring and in the README; (6) a seam search with a shuffled control proves only whole maps and lower halves.
- Keep the `26:7080` fingerprint of the Pocket Camera (Japan) Rev A in mind for every other ROM (README 16.25.2): a 576-byte full-screen tile map (20 visible columns, `$A5` hidden columns, 245 distinct ids numbered by first use in a descending raster, a 4-column strip, a 16-column picture, two small blocks, one background id 63 times) that has no tile set, no loader and no look-alike in the two Pocket Camera ROMs. On a new ROM run `tcrf_check/tools/map_pattern_match2.py` (a copy scores near 1.000, unrelated windows 0.13-0.16) and then `tile_seam_offsets.py` at the match; a hit would give the missing tile set (HOWTO_NEW_ROM.md, Stage C item 6).
- Recompute every number before quoting it; regenerate derived tables with the tool. Corrections made in this project: a variable declared "never written" (only its reader was dead), a description of a branch flip written backwards, a count taken from the wrong column.

## Discipline

Tag claims C / I / ?; never guess, say what was not checked. Run the repository's consistency checker (`tools/check_repo_consistency.py --rom ROM --roundtrip`) before every commit. Keep the owner's answers in a CSV. Update README and checklist files together. One commit per batch: `git fetch origin`, `git merge-base --is-ancestor origin/main HEAD`, `git push origin <branch>:main`.

## Answering "how far are we from a full disassembly?"

Never give one percentage. Give the level table (L0-L6), the measured counts behind each level (bytes by type, names by tag, raw RAM operand lines, auto labels left, doubtful rows with distinct bytes), and the next step with the best payoff (apply the RAM map).
